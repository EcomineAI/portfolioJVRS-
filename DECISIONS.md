# Design & Tech Decisions

Why the portfolio is built the way it is. Each decision names the **UI/UX principle** it serves (from the course: clear navigation, readable content, consistent design, usability, accessibility) so I can explain and defend it.

| # | Decision | Principle | Why |
|---|---|---|---|
| 1 | Nav labels are **Home / About / Projects / Case Study / Contact** | Clear navigation | Matches the prof's suggested structure and what visitors expect. Creative names (Code / Create / Learn) only appear *inside* Projects as groups, never as top-level menu items. |
| 2 | **Case study is one click from every page** (nav item) and the first, biggest card on Home and Projects | Clear navigation, visual hierarchy | The software engineering project is the most important item for graders, so it gets the strongest position. |
| 3 | **Multi-page site** (React Router) instead of one long scroll | Clear navigation, usability | Each required section has its own URL that can be linked, bookmarked and shared. Back button works as expected. |
| 4 | **Pixel-art Warm Paper & Charcoal Ink visual style** (Press Start 2P + VT323, 0 radius, 4px borders, hard neutral shadows; Warm Paper `#f4f1ea` / True Graphite `#111214` with Cobalt `#1d4ed8` primary and grounded PCB Green / Signal Crimson / Brass Ochre world inks) | Consistent design | Deliberate retro hardware & indie print identity free of pastel/purple gradients. One token file (`src/styles/tokens.css`) drives every surface, border, and high-contrast ink pair across both themes. |
| 5 | **Readable font for long text** (Space Grotesk); pixel fonts only for headings, labels and short UI text, Press Start 2P never below 16px | Readable content | Pixel fonts are hard to read in paragraphs. The trade-off keeps the style without hurting readability. Prose is capped at ~68 characters per line. |
| 6 | **Light and dark themes**, follows the system setting, remembered after toggling | Usability, accessibility | Respects user preference; no flash of the wrong theme on load. |
| 7 | **Color contrast ≥ 4.5:1** for all text in both themes (muted text and button colors were darkened from the reference) | Accessibility | WCAG AA. The reference site's light-blue muted text was too faint on white. |
| 8 | **Visible focus ring, skip-to-content link, semantic landmarks, one `<h1>` per page** | Accessibility | Keyboard and screen-reader users can navigate as easily as mouse users. |
| 9 | **Mobile-first responsive layouts** (tap targets ≥ 44px, compact dropdown mobile menu, 2-col mobile hero, straight 3D keyboard with fixed-height readout, inline 16:9 project card thumbnails, slim About console, 2-col certificates, horizontal Developer ID card), tested at 360 / 390 / 768 / 1280px | Usability (mobile) | Prof requires mobile + desktop. Replaces desktop-zoom compression with tailored mobile layouts and zero horizontal page scroll on phones. |
| 10 | **Spray paint is opt-in and never blocks the page**: only starts after holding on an empty spot, ignores links/buttons/inputs, can be switched off, touch requires turning on spray mode | Usability | A fun feature must not break clicking, selecting text or scrolling. |
| 11 | **Pixel buddies stay on the Home hero floor by default; roaming the whole site is opt-in** ("Explore the site" in their menu, remembered). When roaming they stand on top of cards, follow the visitor when they scroll or change page, are real buttons with labels, and stop moving with "reduce motion" | Accessibility, usability | Delight without covering content by default; visitors who want more can let them keep them company on every page. Trade-off when roaming: while standing on a card they can briefly cover a little of the content just above it; they never block scrolling, the layer ignores clicks except on the buddies themselves, and any card can opt out with `data-buddy-ignore`. Keyboard and screen-reader friendly. |
| 12 | **`prefers-reduced-motion` respected everywhere** (no physics, no wandering, no typewriter) | Accessibility | Motion can cause discomfort for some users. |
| 13 | **Skills shown as "LVL = number of my projects that use it"** instead of made-up percentages | Honest, readable content | Every level can be checked against real projects; easy to defend. |
| 14 | **GitHub activity widget** with 2D grid and 3D skyline, plus a text summary and table | Readable content, accessibility | Shows real, recent work. The canvas is decorative; the same data is available as text. |
| 15 | **Team projects always show "My role" and "My contributions"** | Honest content (prof requirement R3) | Makes clear what I did vs. teammates. |
| 16 | **Contact = EmailJS direct email form (`DirectEmailForm`) + Copy/Gmail + McLovin Developer ID card (with scannable LinkedIn QR) + GitHub, LinkedIn, OnlineJobs.ph, résumé** | Usability | Visitors can message directly without leaving the site (with graceful Gmail fallback if EmailJS env vars aren't configured), or grab the résumé/socials from the "Say hi" bar that ends every page. |
| 17 | **Vite + React + plain CSS**, no UI framework | Performance, maintainability | Small bundle, fast load, and I understand every line of styling. |
| 18 | **Hosted on Vercel**, SPA rewrite so deep links work | Usability | Direct links like `/case-study` load correctly. Live on purchased custom domain [`www.junevicabello.site`](https://www.junevicabello.site). |
| 20 | **Dot-matrix hero**: my name and portrait are drawn as pixels that move away from the cursor; the real name is in the `<h1>` as screen-reader text and the canvases are decorative | Consistent design, accessibility | Memorable first impression that matches the pixel theme, without hiding content from assistive tech. Photo is cropped and masked so only my face/shoulders are used. |
| 21 | **Monochrome stepped animated pixel-gradient background & pixel-grain overlay** (`PixelBackground.jsx` in warm stone/charcoal light & bone/ash dark tones, quantized to 5 stepped levels at 10 FPS, fades toward the bottom, stops with "reduce motion") | Readable content, accessibility | Keeps the signature animated retro-pixel atmosphere strictly in neutral light/dark tones without blue/purple color washes competing with content. |
| 22 | **Text never sits directly on the busy background**: lists are boxed cards, headings/intros/paragraphs get a solid backing | Readable content | Fixes low readability of small text over the grid and animated pixels. |
| 23 | **Wider layout (max 1440px)** | Usability on large screens | Uses the left/right space on desktop; long text still capped at ~68 characters per line. |
| 24 | **"Bug Attack" is opt-in, locked while it runs, and fully reversible**: it only starts from its header button. While it runs, the site is locked into the fight (links and Back are blocked) until the bugs are beaten or the visitor presses the bug button again to retreat; Escape does nothing. The page damage is an overlay removed at the end. Sound is on by default with a remembered mute toggle. Reduced motion turns off flashing, shaking, slow-mo and zoom | Usability, accessibility | A memorable, game-like easter egg for visitors who want it. There's always one clear, keyboard-reachable way out (the button), and the content is never really broken. |
| 25 | **Skills as a 3D keycap board in the hero**: 24 logo keys (6 × 4) beside the name. Clicking a key opens the description (its projects); clicking it again or pressing Esc closes it. The board spins in and the keys drop on a fresh page load only | Consistent design, usability | Turns the skill list into something playful that still shows evidence. The description only opens on purpose, so it never gets in the way. |
| 26 | **Skill categories grouped by type** (Languages, Frontend, Backend & data, AI / LLM, Automation, Design & 3D, Editors & IDEs, Dev workflow). Tools with no project yet show a "daily tool" note instead of a count | Clear navigation, honest content | Related tools are easier to scan, and no project count is invented. |
| 27 | **Certificates are pictures** in a grid, and clicking one opens it large. Each certificate is one entry in a single data file | Clear content, usability | Adding a certificate is just dropping in an image and one line of data. |
| 28 | **Case Study (`/case-study`) uses a campus corkboard + locker + notebook theme**: corkboard hero with desktop right-side preview, sticky pixel school locker TOC (`CS-01`), and full-width lined notebook sheets (`01`–`08`) with crisp white/cream index cards, kraft masking tape, and solid accent top rules | Consistent design, visual hierarchy | Grounds the Askademic campus consultation story in tactile academic motifs using high-contrast index cards instead of pastel sticky notes. |
| 29 | **Featured Case Study card on `/projects` pairs copy with a retro browser preview** (`>= 960px` 2-col, stacked on mobile), and **`03 · Learn` covers 4 topics** with verified local cover photos | Visual hierarchy, consistent design | Eliminates dead whitespace on wide screens and gives every Code / Create / Learn card a real visual preview on both desktop and mobile. |
| 19 | **AI tools used for assistance** (planning, scaffolding, code); all text and design reviewed and personalized by me | Course rule R6 | Used AI to scaffold layout components and CSS/animation boilerplate, then personally customized the pixel-art design tokens, interactive features (Askademic case study, GC-Assist overview, keycap sounds, buddies, Bug Attack), and rewrote project and bio copy to match my own projects and voice. |
